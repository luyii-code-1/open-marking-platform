## 实际验证结果

使用独立模拟考试、100名模拟学生、100个教师账号及100份生成的扫描JPEG，完成：

1. 制卡发布、应考名单、HTTPS上传、真实Redis/Worker识别及配页；100个考号准确匹配。
2. 100个教师领取不同作答，鉴权读取答题图。
3. 100条教师WSS连接、全部应用心跳、100个同时发起的评分请求及实时通知。
4. 成绩发布；客观题3分加主观题10分，每人总分13分；CSV导出100行。
5. 后台归档、HTTPS下载SHA-256核对、释放本地扫描文件、答题图从归档按需回取、完整恢复；100人成绩保留。

恢复时先按需回取1个校正文件，再批量恢复199个文件。成功续跑阶段耗时99.6秒，不含此前已经完成的账户准备与扫描阶段。负载生成器采用异步HTTP/WSS，使用与前端相同的JSON心跳；没有操作浏览器界面。

100个评分请求同时提交的确认时间：P50约5.73秒、P95约7.60秒、最大约7.77秒；完成评分及全部通知约7.89秒。该突发负载下延迟偏高，且API只分配0.5核，不能据此判定原定4核8GB、1200人×9科的生产容量通过。领题阶段复用了先前已验证的有效租约，本报告不提供领题延迟基准。

机器可读结果见 [内网验证结果](内网验证结果.json)。

## 现场发现及更新

为按IP访问补充Caddy的 `default_sni`，保持TLS验证开启；该配置用于客户端未提供SNI时选择站点证书，见 [Caddy官方说明](https://caddyserver.com/docs/caddyfile/options#default-sni)。为低配机器启动过程补充测试CA就绪等待。

修复客户端突然断开时，服务端重复关闭连接可能抛出WebSocketDisconnect的问题，针对性3项实时通道回归通过。部署r2镜像后重新检查：100人成绩仍为13分、历史答题图可读、突然断开不产生ASGI异常，已有服务继续运行。见 [内网更新后验证](内网更新后验证.json)。
