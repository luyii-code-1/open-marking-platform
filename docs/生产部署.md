## 目录与启动方式

拟使用`/opt/openmarkingplatform/releases/<部署版本>`保存源码和配置，`/opt/openmarkingplatform/current`指向当前版本；全新业务数据位于`/srv/openmarkingplatform/data`。Caddy证书及Redis数据使用Compose独立卷，项目名固定为`omp-production`。

在版本目录中，将`deploy/production.env.example`复制为`.env`，填入三个镜像引用，然后使用：

```sh
docker compose -p omp-production -f compose.yaml -f deploy/compose.production.yaml config --quiet
docker compose -p omp-production -f compose.yaml -f deploy/compose.production.yaml up -d --no-build --wait redis api worker scheduler
```

配置中的三个镜像需提前导入并按部署清单核对。API、Worker和调度器共用同一应用镜像，API和Redis不发布公网端口。DNS未就绪时先启动上述后端服务，待解析正确后启用Caddy的80/443入口。此过程不调用管理员初始化接口。

## DNS与首次初始化

DNS新增`omp`的A记录，指向`110.42.41.89`。域名解析正确、80/443可达后，由Caddy自动申请及续期公开证书。DNS未就绪时，不能将公开HTTPS标记为已验收。

```sh
docker compose -p omp-production -f compose.yaml -f deploy/compose.production.yaml up -d --no-build --wait proxy
```

证书就绪后，用户访问`https://omp.gfzx.com`，选择“管理后台”，进入“创建管理员”完成首次初始化。随后按生产实际情况创建人员和考试，并在系统设置中添加正式存储连接。

验收采用服务健康检查、Worker及Redis连通检查、数据库业务记录为空核对、HTTP到HTTPS跳转和最终公开证书校验；本次初始化期间不创建测试管理员或模拟考试。

参考：[Docker Ubuntu安装](https://docs.docker.com/engine/install/ubuntu/)、[Caddy自动HTTPS](https://caddyserver.com/docs/automatic-https)。
