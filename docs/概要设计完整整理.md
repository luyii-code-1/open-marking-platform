### 一、项目名称、组成与总体要求

来源：PDF 第 2 页。

项目名称：**Open Marking Platform，开源全流程阅卷系统（概要设计）**，简称 **OMP**。

- 后端：Python + FastAPI，Redis + SQLite3。原文 Redis 字样写作近似 `Redius`。

```text

            ↓
       xxxxx_x.PNG
       考号  面
            ↓ 校正、压缩
          JPG
            ↓ 后端记录
         ROS 储存
```

```text
客户端（阅卷）：EOPage → PWA 框架（worker.js）

PWA 框架
   ↑ WSS
服务端：HTTPS（VPS）
```

`EOPage` 为原图中可辨认的拼写，其具体所指未在文档中解释。

#### 4. 功能范围

1. 制卡。
2. 扫描。
3. 题卡预处理。
4. 在线阅卷。
5. 分析。
6. 归档。

### 二、后台管理、考试结构与基础数据

来源：PDF 第 1 页；第 3 页为同一主体内容的重复拍摄。

#### 1. 项目式考试管理

- 一次考试为一个项目。
- 一个项目下可以有多个科目。
- 一个科目下可以有多个组，用于区分年级或班类，例如“高一（普）”“高一（卓）”。
- 如果不分组，则默认为 `Default` 组。
- 一个组绑定一张题卡。
- 每个组，即其绑定题卡，具有唯一的全局 UUID。
- 原文括注为“仅绑定题材有 UUID”，其中“题材”疑为“题卡”，保留此处辨认说明。

原图举例表达的结构：

```text
项目：模拟考试1、模拟考试2

科目：语文
└─ Default组
   └─ 题卡1

科目：数学
├─ 高一（卓）组 → 题卡2
├─ 高一（奥）组 → 题卡3
├─ 高二（普）组 → 题卡4
└─ 高三组       → ……
```

注：示例中的“奥”按手写字辨认；它是分组名称示例，不是固定组类型。

原文符号说明：`*` 表示“必选一项／仅可选一项”。

#### 2. 项目管理操作

- 创建项目。
- 新增科目。
- 新建组。
- 设置组的题卡。
- 归档并下载：打包所有数据、题卡、已扫描的卷，并提供下载。
- 释放空间：删除已扫描的题卡，需要二次确认。
- 深度归档：进行深度压缩，下次访问需等待解压。**原文标记为后期计划。**

#### 3. 用户管理

- 在内网管理页下载批量模板，格式为 `.csv`。
- 使用模板快速批量创建账号。
- 用户记录其所教班级，原文表述为“用于记录被设置‘教授的班级’”。

#### 4. 班级系统

- 可以创建班级。
- 班级可以分配给用户，即各任教教师。
- 教师可以查看其任教班级的成绩分析。

#### 5. 学生管理

- 同样使用模板快速配置学生。

### 三、制卡

来源：PDF 第 1、3、4、5、6 页。第 3 页重复第 1 页主体，第 6 页重复第 5 页主体。

#### 1. 制卡目的与操作形式

- 产生 A4/A3 的 PDF。

#### S1：新建题卡

支持两个入口：

1. 从已经创建的组新建。
2. 从题卡库新建。

两种创建方式均会产生唯一 UUID，UUID 将打印在题卡上的二维码中。

#### S2：选择版面

- A3。
- A4。

#### S3：基本信息

- 用户填写主标题。
- 用户填写副标题。
- 设置准考证号长度。
- 一边填写，一边生成预览。
- 采用标准制卡，原文注明“见附件”；这份 PDF 中没有能明确对应的独立标准制卡附件图。
- 自动生成提醒、缺考标记部分。

#### S4：设置答题区

采用可视化设置：左侧配置，右侧大比例预览，支持编辑。

##### A. 建立模板

**客观题区**

- 支持 4 项、3 项、5 项等不同选项数量。
- 支持单选与多选。
- 支持不定题号，即题号不连续；适合语文等选择题分散的科目。
- 原文举例：可以是 `1、2、5、6`，而不是只能为 `1、2、3、4`。
- 用户点击创建“（ ）项选择题”后，在预览中自动渲染。括号中的内容在原文留空，表示待填写的选项数。
- 用户可以点击预览中的题目进行快速编辑。
- 可编辑题号、选项数、分值、答案。
- 客观题区单独使用一个区域框出。
- 用户可以进入快速设置答案模式：从第一题开始，数字键 `1～5` 代表 `A～E`。

**主观题区**

- 用户可以设置、新建主观题区块。
- 主观题答题模板可包含自定义行数的横线。
- 支持作文格。
- 支持富文本、图表等多种内容。
- 支持从 Word 等来源带格式粘贴，或导入图片。

**所有题目的答题区规则**

- 所有题目均使用黑框表示答题区，即截题区。
- 一个题号可以有多个答题区。
- 阅卷时自动拼接同题的多个答题区并显示。

##### B. 从已有题卡处理

- 如果试卷已有三方题卡，可以用其扫描件快速制作。
- 标题等内容自动覆盖。
- 原有客观题区不支持直接兼容，需要覆盖并重新制作。
- 主观题需要手动建题，并手动框出答题区。

- 是否设置分值。
- 其他同类配置完整性问题，原文以“等”收尾。

#### S7：设置答案并自动审查

#### S8：导出打印稿并保存

### 五、客户端之一：扫描端

来源：PDF 第 5、6、9 页；第 2 页另有流程示意。

#### 1. 编写语言设想

- 计划采用 Rust 编写，以提高稳定性。

#### 2. 与扫描机连接

- 原文标记为“待定”。

#### 3. 与服务器连接、鉴权

- 与服务器使用 TLS 自定义协议。
- 连接使用 IP + 端口。
- IP 由域名 DNS 得到。
- 或使用 QUIC，原文注明“需服务器备案”。该条件仅记录原文，并不作为已核实的协议要求。

#### 4. 上传

- 在客户端完成 JPEG 压缩后上传服务器。
- 服务器进行归类处理后存入 ROS。

#### 5. 扫描端的实时基本检查

- 每扫入一张题卡，立刻进行实时基本检查。
- 尽量立即发现基本异常。
- 例子包含信息缺失、卷面破损、虚焦等。
- 发现异常立即中断扫描，便于管理员检查。

#### 6. 校验与上传队列

- 通过基本检查的试卷，计算 CRC 或 SHA-256。
- 进入上传队列。
- 服务器继续进行具体识别与入库。

### 八、多评与仲裁

来源：PDF 第 8 页。

- 一般用于语文作文或英语作文。
- 由两个或以上教师评分。
- 若差值小于某个可设置的值，最终给分取两者平均值。
- 因此评分记录需要区分教师的给分与最终采用的“实际给分”。
- 差值过大时，记录该情况，重新进入仲裁池。
- 由第三位教师一次给出最终分。
- 第三位教师可以从任务分配中的教师随机选取。
- 也可以在指定的几位教师中随机选取，或固定指定。
- 随机选取时，不得选中已经给该作答评分的教师。

原文的“小于阈值”和“差值过大”没有明确覆盖“恰好等于阈值”的情况；后续对话确认的边界见第二部分。

- 9 门科目。
- 约 100 人同时阅卷。

### 3. 分组的含义

- 组对应题卡，是题卡的最小基本业务单位。
- 上级都是用来分类的。
- 不同学校通过题卡组区分。
- 管理员分发账号，教师直接登录使用。
- 题卡上的考场填写栏本身不用于后续成绩业务。
- 教师实际按一个考场一堆纸整理后扫描。
- 扫描时可以手动记录考场，方便后期排查。

### 4. 打印与纸型

- 打印时使用同一份 PDF 批量打印，无法给每份纸张差异化打印。
- 同一科目的版面固定，不同科目之间可能不同。
- A3 一般为单面，少数为双面。
- A4 基本为双面。
- 扫描仪支持 A3 整面扫描。
- 只在正面填涂考号等识别信息。

### 5. 扫描操作

- 同一批题卡不会混入其他考卷。
- 扫描端提供“扫描的考卷”选择。
- 先选择考卷，再开始扫入。
- 双面卷通常先将全部正面扫一遍。
- 再将吐出的整堆纸翻面放入，扫描第二遍。
- 采用顺序配对并由操作员确认批次。
- 遇到其他考卷直接中断，要求人工处理。
- 考场可作为扫描备注，用于管理和排查。

### 6. 已接受的技术方向

- Python/FastAPI 服务端。
- React/TypeScript 前端。
- C#/.NET 扫描端；讨论方案中采用 NAPS2 SDK。
- Redis + SQLite 数据方案。
- 前端组件体系采用 Ant Design。
- 用户提出 GPL-3.0 许可方向；精确的 `only` 或 `or-later` 写法尚未由用户单独确认。
- Web UI 审查由用户本人完成。
- 常规界面保持足够留白、降低信息密度；登录页聚焦登录操作，各页面文案服务于业务操作。

### 7. 用户已确认的评分与发布规则

- 双评盲评。
- 差值小于或等于阈值时取平均值；超过阈值由第三评直接仲裁。
- 冻结前教师可以回评。
- 管理员检查异常后确认发布成绩。
- 选科赋分支持配置分段与导入对照表。
- 分数步长、阈值、客观题给分规则和赋分参数可以配置。
- 应考名单存在未扫描学生时，管理员可以明确确认后强制发布；这些学生标为“未扫描”，不按缺考零分处理。

### 8. 用户确认的空间释放范围

- 允许释放服务器本地及远端存储中的扫描卷。
- 每次操作应明确选择范围，并先核对归档和释放清单、再次确认。
- 释放扫描卷不删除成绩、审计记录或用于恢复的有效归档；“本地及远端均可释放”是可选操作范围，不代表每次都必须同时释放两端。
