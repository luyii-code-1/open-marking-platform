# 备份与恢复

## 保存恢复材料

`POST /api/v1/system/backup` 创建一致的SQLite备份，返回编号、SHA-256、大小、记录数量与下载地址。`GET /api/v1/system/backups` 列出登记备份及文件是否仍可用；下载接口仅限管理员，并核对登记的校验值。备份文件保存在数据目录的 `backups/<UUID>.sqlite3`。

数据库与文件应按同一恢复点保管。文件材料包括 `pages/` 扫描原件和校正图、`assets/` 题卡/特殊卷资产、`archives/` 项目归档ZIP。需要可靠的文件快照时，暂停API、Worker和调度器写入后保存这些目录及数据库。远端保存唯一副本时，先同步到文件快照；已释放扫描卷可由保留的项目归档补回。

生产容器停写后可通过一次性容器创建数据库备份：

```sh
docker compose stop api worker scheduler
docker compose run --rm --no-deps api python -c 'import json; from server.backups import create; print(json.dumps(create(None)))'
```

保管输出中的编号与SHA-256，并保存对应文件目录的快照。环境配置、存储凭据与服务器TLS材料按部署流程独立保管。

## 恢复到新目录

恢复工具要求目标目录尚不存在、父目录已经存在；不会覆盖原数据目录。数据库校验、文件版本校验及归档补卷成功后，才发布新的数据目录；失败会中止，并保留原备份和源文件。

在仓库根目录执行，替换下面的备份路径、目录及校验值：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m server.recovery "F:\OMP-snapshot\backups\备份UUID.sqlite3" --target "F:\OMP-recovery\data" --files-from "F:\OMP-snapshot" --sha256 "备份返回的SHA256" --reason "恢复演练"
```

`--files-from` 指向包含pages、assets、archives的目录。工具按备份中的记录恢复所需文件，先复制归档ZIP，再从归档补回已释放的扫描文件。已有文件与已登记哈希不符、缺失所需文件或归档版本不匹配时中止。

若只需恢复数据库供核查，可显式指定 `--database-only`，此时不使用 `--files-from`。报告会标记文件未恢复；启动前仍需按用途补齐文件及外存配置。

成功后，目标目录包含 `omp.sqlite3`、恢复的文件及 `recovery-report.json`。报告列出原始与恢复后的记录数量、文件复制/归档补回数量及运行状态重置数量。历史记录若没有保存文件哈希，会计入 `without_recorded_hash`；这些文件仅完成复制，不能据此证明与备份时版本一致。新上传资产及人工定位历史资产已记录哈希。

## 恢复后的运行状态

成绩、给分流水、原审计、用户资料及编号保留到备份时的状态。恢复会新增恢复事件，并处理会立即影响运行的状态：

- 清除旧登录会话，失效旧下载凭证、验证挑战及恢复码；账号密码和Passkey记录保留，重新登录后可生成新的恢复码。
- 停用扫描设备授权，管理员核查并重新启用后连接。
- 将未完成后台任务置为待人工核查的失败状态；管理员确认后重试。旧队列消息不会直接执行失败任务。
- 使未完成的空间释放清单过期，重新生成预览并确认；原评阅租约及项目文件操作锁一并解除。

这些变化及数量记录在恢复报告中。恢复不合并备份之后的新数据，原数据目录应继续保留，便于对照。

## Linux容器演练与切换

Compose的API、Worker和调度器统一使用 `OMP_HOST_DATA` 作为宿主机数据目录，默认 `./data`。以下恢复命令仍读取原挂载目录，并写入新的独立目录；替换编号与SHA-256：

```sh
mkdir -p /srv/omp-recovery
docker compose run --rm --no-deps -v /srv/omp-recovery:/recovery api python -m server.recovery /data/backups/备份UUID.sqlite3 --target /recovery/data --files-from /data --sha256 备份返回的SHA256 --reason 恢复演练
```

核对报告后，将 `.env` 中 `OMP_HOST_DATA` 指向新目录，例如 `/srv/omp-recovery/data`，再启动服务。确认登录、题卡打印、历史阅卷图片、成绩及设备授权后完成切换。原目录继续保留；更改外存配置前核对原远端目录与访问凭据。

开发环境已验证原生Windows新目录恢复及服务重启，覆盖归档补卷、成绩/评分流水/审计保留、会话和设备失效、任务暂停、拒绝覆盖、哈希错误和实际CLI。生产全量与Linux容器切换仍待部署环境演练。
