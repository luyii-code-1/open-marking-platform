# 安装与交付

当前交付为开发预览，用于部署联调和人工验收。项目许可已确定为GPL-3.0-only，扫描端目标为.NET 10。真实扫描仪与用户界面验收仍需完成，正式生产部署按用户安排在后续进行。

## 构建交付包

在仓库根目录执行，需Python、Node/npm及当前扫描项目对应的.NET SDK：

```powershell
python -m pip install -r requirements.txt -r scanner_engine/requirements-build.txt
python -m tools.package_preview
```

脚本依据前端锁文件安装依赖、构建前端并验证层级导航、客观题排布与PWA隔离行为，发布Windows x64扫描端，输出到新的 `dist/preview-时间/`。可用 `--output 新目录` 指定位置；已有目录会被拒绝，避免覆盖旧交付物。

- `OpenMarkingPlatform-source-preview.zip`：服务端、前端源码及已构建页面、扫描端源码、部署配置、测试与文档。可用于Linux容器构建或本地运行。
- `OpenMarkingPlatform-scanner-win-x64-preview.zip`：扫描程序、离线网页、随包Python/OpenCV识读引擎及其依赖；解压整个目录后运行 `OMP.Scanner.exe`。
- `SHA256SUMS.txt`、`release.json`：产物校验值、体积及待验收事项。每个ZIP还含逐文件 `BUILD-MANIFEST.json`。

构建包不携带运行数据库、扫描队列、设备私钥或部署 `.env`。应用数据迁移按《备份与恢复》处理。构建失败时输出目录可能保留已完成的部分产物；只有两份ZIP及最终 `release.json` 全部生成才算本次打包成功。

Windows可通过以下命令核对下载后的ZIP，与 `SHA256SUMS.txt` 对照：

```powershell
Get-FileHash .\OpenMarkingPlatform-source-preview.zip -Algorithm SHA256
Get-FileHash .\OpenMarkingPlatform-scanner-win-x64-preview.zip -Algorithm SHA256
```

## 服务端安装

解压源码包至独立目录。Linux部署按《部署与存储》配置 `.env`、域名和本地数据目录，再执行 `docker compose up -d --build`。容器构建需要访问npm、PyPI和系统软件仓库；当前包不包含离线依赖镜像。

首次从HTTPS站点创建管理员，创建人员、班级与任教关系，再建立考试、科目、题卡组及题卡。先用小规模测试项目完成打印、扫描、配页、评阅、发布、归档与恢复，再导入正式考试。Web界面由用户本人验收。

本地联调可按README创建Python虚拟环境并启动Uvicorn；源码包内的 `web/dist` 可直接由服务端提供，前端改动后需要重新构建。

## 扫描端安装与更新

当前预览以 `net10.0-windows`、Windows x64、依赖框架方式发布，需要.NET 10 Windows Desktop Runtime、Microsoft Edge WebView2 Runtime及扫描仪厂商驱动；Python运行时随识读引擎提供。发布包未签名，不提供安装器或自动更新。

解压后可通过 `python -m tools.scanner_smoke --scanner-dll 解压目录/OMP.Scanner.dll` 进行无窗口联调（需开发Python依赖、当前.NET运行时及Poppler）。本次预览已用实际解压产物验证设备签名、持久队列、质量冻结、JPEG上传和配页结分；此检查不替代真实扫描仪验收。

项目式扫描、离线重启及随包引擎联调用`python -m tools.desktop_scanner_smoke --scanner-dll 解压目录/OMP.Scanner.dll --bundled`。这条开发验证命令需要测试工具依赖；日常运行扫描程序不需要安装Python。扫描端工作区设计和正常使用见《扫描端工作区架构》。

解压全部文件到独立目录，连接扫描仪并安装厂商驱动。启动 `OMP.Scanner.exe`，填写HTTPS服务地址，按《扫描端》完成管理员注册与设备授权。WIA/TWAIN/ESCL和实际ADF能力需要在设备上确认。

更新时先停止采集并退出客户端，再把新包解压到新的程序目录。扫描队列默认位于 `%LOCALAPPDATA%\OpenMarkingPlatform\Scanner`，设备身份与Windows用户绑定；更新程序目录不需要删除队列或重新生成密钥。更换电脑、Windows用户或服务地址时按设备迁移流程处理，先核对待上传文件。

## 服务端更新与回退

更新前创建数据库一致备份并保留文件资产，记录当前程序版本与 `.env`。安排停止扫描和阅卷，停止旧容器后在新源码目录构建，用原数据目录启动新服务；检查健康状态、管理员登录、样本题卡及成绩读取。

回退时停止新容器，使用更新前备份恢复到新数据目录，再以旧源码和对应配置启动。恢复会撤销会话、设备授权等运行凭据，需按《备份与恢复》重新授权与核查任务。不要假定旧程序可以直接读取新程序修改后的数据库。
