# ROS 媒体处理接入核对

资料来源：用户于2026-11-12粘贴的“媒体处理 Beta”控制台参数说明。该说明补齐了在线裁切、缩放和格式转换参数；私有桶签名及实际处理域名尚需确认。Beta期间暂不收费、正式上线另行通知为资料中的当时说明，实际计费以服务商届时公告为准。

## 已确认的参数说明

| 参数 | 含义 |
| --- | --- |
| `rect=x,y,w,h` | 在原图中按像素裁切，先于缩放执行 |
| `w`、`h` | 目标宽高，单位像素 |
| `dpr` | 尺寸倍率，默认1 |
| `mode=clip` | 等比装入目标框 |
| `mode=crop`、`pos` | 铺满后裁切及保留位置；默认crop |
| `fmt` | jpg/jpeg、png、webp、avif、gif |
| `q` | JPEG/WebP/AVIF质量1–100，PNG基本忽略 |

说明还列出锐化、模糊、文字与图片水印；本次接入目标是阅卷题图的坐标裁切与按需缩放。

## 与当前系统的衔接

题卡区域使用毫米，校正图固定每毫米4像素。应当基于校正图裁切；原始扫描图尚未校正，不能直接使用题卡区域坐标。沿用现有Pillow裁切边界：`left=int(x*4)`、`top=int(y*4)`、`right=int((x+width)*4)`、`bottom=int((y+height)*4)`；ROS矩形为`left,top,right-left,bottom-top`。例如区域`x=15,y=110,width=90,height=20`对应`rect=60,440,360,80`。

扫描端上传的切题包继续优先使用；ROS可用于远端校正图的单区域按需裁切。多区域、跨面作答仍需按现有顺序拼接，该说明没有列出拼接接口。特殊卷覆盖图片继续按其独立资产处理。

若教师浏览器直接从ROS获取题图，题图流量由ROS承担，可降低应用服务器出网负担；若应用服务器代取并转发，服务器仍需向教师发送图片，不能据此降低服务器出网配置。当前`/tasks/{id}/image`仍为鉴权取图及服务端转发，本次仅完成参数与方案核对，尚未切换取图链路。

## 接入前仍需确定

1. 图片媒体处理使用的实际访问域名、路径格式，是否与S3 API endpoint相同。
2. 私有桶的`rect`等处理参数怎样参与预签名，是否允许在已签名URL后追加，以及参数修改后服务端怎样验证。现有S3辅助方法只签署普通GetObject URL，不能直接推定追加处理参数后的兼容性。
3. 教师直链应只授权指定题图。需要用实际私有桶确认更改/移除裁切参数的行为，避免匿名阅卷时暴露含身份信息的整页；未核对前沿用现有鉴权题图链路。
