# 阅卷API并发验证

## 数据与方法

`tools/benchmark.py` 使用临时目录中的独立SQLite数据库，构造10800份答卷、9份科目题卡、10800条历史评分任务及100名教师。通过ASGI客户端执行每位教师领取一份作答并提交分数，检查成功数及任务唯一性。结束后删除临时测试数据。

该测试不包含图片传输、真实网络、Redis Worker和部署服务器，不能替代生产环境全链路压测。

## 当前观察结果

| 负载 | 成功人数 | 重复任务 | 错误 | 组合请求P95 | 评分确认P95 |
|---|---:|---:|---:|---:|---:|
| 100人同时发起 | 100 | 0 | 0 | 2.338秒 | 该次未分别记录 |
| 100人，每秒20人发起 | 100 | 0 | 0 | 0.040秒 | 0.019秒 |

组合请求指领取及评分两次请求。数值为本次Windows开发机观察值，不作为其他硬件的性能承诺。

## 已修正的问题

- 领取与完成评分按题目、答卷、教师建立并使用索引。
- 将最终评分缓存置于同一事务更新，更正答卷时同时失效缓存。
- 修正关联UUID比较中的SQLite类型亲和性，避免JSON表达式索引退化为全任务扫描。
- 同一API进程中的写事务串行入场，保留SQLite对跨进程写入的协调。
- 过期的本人领取记录不再直接续期，先失效再参与当前任务分配。

## 重现

```powershell
.\.venv\Scripts\python.exe -X utf8 -m tools.benchmark --users 100 --submissions 10800
.\.venv\Scripts\python.exe -X utf8 -m tools.benchmark --users 100 --submissions 10800 --rate 20
```

可设置 `OMP_SQL_PROFILE=1` 输出开发用SQL耗时汇总；输出不包含SQL参数值。

## 权重分配接入后的复测（2026-11-12）

任务领取加入持久化教师份额、分配配置检查及跳过排序后，以同一工具重新执行每秒20人负载：10800份答卷、10800条历史任务、100位教师，领取并评分成功100人，无错误，任务ID均不同。组合P50为0.068秒、P95为0.229秒，评分确认P95为0.112秒。本次同时运行了后端测试与前端构建，不能直接用数值差推导单个改动的开销。

新行为包含首次生成教师份额；后续领取复用持久化结果。上述结果仍仅覆盖开发机内进程ASGI，不包含生产部署、图片传输、真实Redis或扫描设备。
